# Temporal-analysis release contract

This document records the TEPP-owned consumer boundary needed by downstream workforce-validation adapters such as Orgmetra. It does not declare a released artifact. GitHub release, package, provenance, SBOM, rollback, reproducibility, exact-head checks, and independent review remain separate release gates.

## Existing owner surface

The release path reuses `tepp_api::AnalysisRunRequest`, `AnalysisRunAccepted`, `AnalysisRunStatus`, and `AnalysisRunTerminalResult`; it does not create an Orgmetra-specific analysis schema or copy TEPP source into a consumer repository. Request identity already binds the immutable snapshot, knowledge cutoff, model/backend contract version, and requested output profile. A successful terminal result binds the run and request identity to an opaque result artifact, canonical lowercase SHA-256, result-schema version, canonical completion time, and bounded summary.

`AnalysisRunRequest::to_json` treats the knowledge cutoff as a structural wire coordinate. The cutoff must use TEPP's canonical UTC RFC 3339 spelling; a semantically equivalent offset spelling is rejected rather than permitted to create a second valid byte identity for the same instant. Serialization does not consult the current wall clock. Live `AnalysisRunRequest::from_json` remains the admission boundary and additionally rejects a canonical cutoff that has not happened yet. The split is deliberate: immutable request evidence must preserve one stable byte identity during later replay, while a new command still cannot claim evidence availability from the future.

`AnalysisRunTerminalResult.completed_at` follows the same byte-identity rule. The supplied system-time text must equal TEPP's normalized UTC RFC 3339 spelling, so timezone-offset aliases cannot produce multiple valid immutable terminal-result byte identities for one completion instant. This rule does not collapse system time into knowledge cutoff: historical analyses may legitimately complete at a system time that is not ordered after the analysis cutoff, because the clocks carry different semantics.

The digest-bound TRSL topic-lineage artifact applies the same rule to its own `knowledge_cutoff`. The artifact refuses semantically equivalent offset aliases and accepts only `KnowledgeCutoff::to_rfc3339()` output, so one historical estimator cutoff instant cannot produce multiple valid artifact byte strings or SHA-256 digests after request admission has already been canonicalized.

The unreleased TRSL topic-lineage consumer pair is now output profile `trsl_topic_lineage_v2` plus artifact schema `tepp.trsl_topic_lineage.v2`. Version 2 retains the exact canonical estimator configuration as `method_configuration_json`, binds those bytes with `method_configuration_sha256`, and records `model_contract_version = trsl_tm_cpu_f64_v1` plus `estimator_backend = cpu_f64_reference`. The configuration itself has the closed schema `tepp.trsl_topic_lineage.reference_config.v1` and carries topic count, ordered seed set, maximum iteration budget, tolerance, prior variance, relation strength, ridge, topic smoothing, and step size. The executor constructs `ReferenceTopicModelConfig` from these retained canonical bytes rather than accepting a detached caller-side config object, so the artifact contains enough owner truth to reconstruct the numerical configuration actually used for fitting.

Configuration validation is fail closed. Unknown or floating configuration schema identities, extra fields, non-canonical JSON spellings, detached configuration digests, invalid numerical controls, a result topic count that differs from the declared configuration, a selected seed outside the declared ordered seed set, or an iteration count above the declared budget invalidate the artifact. The request must name `trsl_topic_lineage_v2`; a historical `trsl_topic_lineage_v1` request cannot silently receive a v2 artifact. Because the v1 profile/artifact pair was not published as an immutable TEPP release, this Draft work does not mutate a released wire shape; the first supported immutable consumer contract must identify the v2 pair explicitly and retain compatibility/rollback evidence at release time.

The v2 artifact also binds `posterior_approximation = diagonal_laplace`, matching the uncertainty representation actually retained by `ReferenceTopicModel`. That label is a scientific claim boundary, not decoration: unknown labels and a stronger `joint_gauss_newton_laplace` claim are rejected. The standalone fitted result explicitly does not retain the fit input required to reconstruct joint coordinate precision, so the consumer contract must not manufacture joint or independent-draw semantics from diagonal variances. A future released projection may expose additional uncertainty quantities only with their own versioned coordinate and parity/recovery evidence.

For the first immutable consumer release, `AnalysisResultSummary.validation_status` has exactly one successful wire value: `validated`. `not_verifiable`, `non_converged`, `insufficient_evidence`, and other non-success scientific states must use `AnalysisRunTerminalResult::failed` and therefore carry no measurement artifact, result digest, result schema, or success summary. This prevents a consumer from treating a provider-authored non-empty status string as scientific success.

The producing domain must use the same shared success vocabulary after its own scientific acceptance. The TRSL topic-lineage executor therefore emits `validation_status = validated` only after the reference estimator returns a converged model and the bounded digest-bound artifact has been constructed successfully. Estimator-specific convergence remains domain evidence; it is not encoded as an alternative success spelling such as `reference_estimator_converged` in the shared terminal summary.

These rules do not make `run_state = succeeded` a general scientific-validity claim outside the exact result contract. The result artifact's temporal/window/cohort semantics, cross-classified or multiple-membership structure, uncertainty quantities beyond the declared diagonal-Laplace approximation identity, broader estimator/evidence provenance, and scientific recovery remain owned by the versioned result schema and the producing TEPP domain boundary. Downstream adapters must consume those released fields without flattening temporal or membership coordinates.

## Release acceptance still open

Issue #638 remains open until a protected TEPP head publishes an immutable versioned package/artifact for this boundary and records the artifact digest, SBOM/provenance, reproducibility and compatibility evidence, rollback path, exact-head tests/security/scientific acceptance, and qualifying independent review. Orgmetra must then pin that immutable owner contract rather than the historical mutable TEPP commit currently named by its adapter documentation.

The current source repairs close nine prerequisites: successful results fail closed unless their validation status is exactly `validated`; the existing TRSL producer uses that canonical success vocabulary after convergence; request serialization no longer depends on the current wall clock; equivalent RFC 3339 offset aliases cannot produce multiple valid request byte identities for one cutoff instant; terminal completion time also has one canonical UTC wire identity; the digest-bound topic-lineage artifact enforces the same canonical UTC cutoff identity before serialization or hashing; the v2 artifact retains and digests the exact reconstructable reference-estimator configuration used by execution; the output profile is versioned with the result schema so a v1 request cannot silently receive v2 bytes; and the artifact explicitly binds the diagonal-Laplace posterior approximation instead of permitting a consumer to infer stronger uncertainty semantics. They do not yet bind the full time/window/cohort, multilevel/cross-classified/multiple-membership coordinates, uncertainty quantities/parity evidence, broader provenance, consumer mismatch fixtures, or immutable release evidence required by #638, and they are not themselves a release, attestation, compatibility guarantee, or authorization for consumer activation.
