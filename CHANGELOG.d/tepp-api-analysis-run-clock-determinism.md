`tepp_api::AnalysisRunRequest` now separates canonical wire serialization from live knowledge-cutoff admission. Canonical request bytes require TEPP's normalized UTC RFC 3339 cutoff spelling and serialize without consulting the current wall clock, while `from_json` continues to reject a cutoff that is still in the future at live admission. Equivalent offset spellings no longer create multiple valid request byte identities for the same cutoff instant. Terminal analysis results likewise require canonical UTC RFC 3339 `completed_at` text, so one completion instant cannot acquire multiple valid immutable-result byte identities through timezone-offset aliases.
