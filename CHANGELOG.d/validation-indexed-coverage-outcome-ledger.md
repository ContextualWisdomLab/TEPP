# Persist exact indexed coverage outcomes in calibration evidence

- `CoverageCalibrationEvidenceRecord` schema v2 now persists the complete exact-permutation coverage outcome ledger in declared replication order instead of retaining only aggregate statistics. Aggregate-identical runs that fail different prospectively declared DGP identities are therefore distinguishable and independently auditable.
- `validation_core::canonical_indexed_coverage_outcomes` reuses the #730 identity contract: the input must be an exact permutation of `0..attempted_replication_count`, while shard/completion order is normalized away. The admitted ledger preserves success/failure identity and every successful rolling-origin coverage value; malformed scientific coverage still fails through the existing aggregation owner before evidence construction.
- The implementation deliberately stores the canonical ledger rather than adding a second digest-only representation. This avoids making a hash the sole recovery path for scientific evidence and keeps `Cargo.lock` unchanged; release/package provenance may hash the resulting immutable evidence artifact separately.
- This change does not execute the prospective 10,000-DGP `tepp.coverage.nominal95.v1` × `tepp.simulation.rolling_origin_coverage.v1` study, define an acceptable numerical-failure rate, promote a scientific claim, or create a release.
